# admin-dashboard · 后台数据看板（Vue 3 + TypeScript）

个人学习项目（第 4 个作品）：一个后台管理系统风格的前端看板。
功能包含 **用户管理**（表格 / 分页 / 搜索筛选 / 新增编辑 / 删除批量）+ **数据概览**（统计卡 + 纯 CSS 柱状图）+ **假登录与路由守卫** + **个人中心**（改密码 / 退出登录）。

线上地址：https://longdandan-dev.github.io/admin-dashboard/

## 功能

### 用户管理

- 表格 8 列：多选框 · ID · 姓名 · 邮箱 · 状态 · 角色 · 创建时间 · 操作
- 分页：每页 10 条、共 100 条；页码与总数联动
- 三态齐全：加载中（转圈）/ 出错提示 / 空结果文案（「没有符合条件的用户，换个条件试试」）
- 新增 / 编辑：**同一个弹窗复用**，编辑自动回填，标题随模式切换
- 表单校验：姓名必填 + 2~10 字；邮箱必填 + 格式校验
- 删除：气泡二次确认；批量删除：多选行 + 确认弹窗（**弹窗里带要删的条数**）
- 搜索与筛选：姓名模糊匹配 + 状态下拉（全部 / 正常 / 待审核 / 已停用）
- 防抖 300ms：连打 4 个字只发 **1 次**请求；点「查询」会掐掉待发的定时器
- **条件一变、页码回第 1 页**（不回的话表格空白，用户以为搜不到）
- 操作反馈：成功 / 失败各有提示；失败时重新拉取，让界面和真相对齐
- **乐观更新**：单条删除先在界面生效（实测 2ms），失败再回滚

## 数据源：这段历史要留着

1. **M2 用的是真接口**：JSONPlaceholder 的 `/posts`（实测 100 条）—— 用它练过「后端分页」和「从响应里取总数」。
2. **M3 起换成本项目内置的 100 条中文假数据**：`src/data/users.ts`（用 Mock.js 生成后落盘，项目里**不留 mockjs 依赖**）。
3. **为什么换**：① 要中文，对齐设计稿 ② 上线是 **GitHub Pages 静态托管，没有后端** ③ 角色 / 状态 / 创建时间这三列，真接口里根本没有。
4. **诚实口径**：这些是**生成的假数据**，不是真实用户。`src/api/user.ts` 是一层"**假接口**"：每个函数都有 300ms 假网络延迟（登录 600ms / 改密码 500ms），返回形状和真接口一致 —— **换回真接口只改这一个文件**。
5. **生成脚本**：`_tools/gen-users-data.cjs`（在工作区的工具目录里，不在本仓库）。三条确定性约定：姓名 100 个不重复 · 角色按 `id % 3` 轮转 · 创建时间铺在 7 天里（每天人数不同，柱状图才看得出高低）。

## 设计

设计令牌--全在 `src/style.css` 的 `:root`：颜色 / 字号（`--fs-*`）/ 间距（4 的倍数）/ 圆角 / 过渡

## 还没做 / 已知限制

头像上传（`el-upload` / FormData）没做
角色权限（菜单按角色变）没做 —— 只做了"登录 / 未登录"
系统设置、订单管理不做（没有对应数据与需求）
数据是假的：刷新页面即还原（没有后端，增删改只改内存）
